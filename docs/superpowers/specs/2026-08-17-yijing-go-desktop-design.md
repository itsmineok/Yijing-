# 弈境 Windows 围棋软件设计

**日期：** 2026-08-17

**状态：** 已确认

**目标平台：** Windows 10/11 x64

**技术路线：** WPF、.NET 10 LTS、MVVM、KataGo

## 1. 产品概述

“弈境”是一款完全离线运行的 Windows 围棋桌面软件。首版提供人机对弈、本地双人对弈、SGF 棋谱保存与载入、胜率与候选落点分析、悔棋、停一手、认输和中国规则数子。

AI 使用 KataGo，不向用户提供难度选择。软件自动检测硬件并选用当前设备上最强且稳定的后端和模型。AI 的正式落子每手最多搜索 30 秒。

## 2. 目标与非目标

### 2.1 目标

- 安装完成后可断网运行，不要求账号或额外下载。
- 支持 19×19、13×13 和 9×9 棋盘。
- 使用中国规则，默认贴 7.5 目。
- 新建人机对局时允许玩家选择执黑、执白或随机执棋。
- 界面保持流畅；KataGo 分析不阻塞 WPF UI 线程。
- GPU 不兼容或启动失败时自动回退到 CPU，不丢失棋局。
- 每次落子后自动保存恢复快照，异常退出后可继续对局。

### 2.2 非目标

- 联网对战、账号、好友和排行榜。
- 云棋谱、云同步和遥测。
- KataGo 模型训练或自我对弈训练。
- 按棋力等级削弱 AI。
- 首版棋谱变化树编辑、逐手讲解或全局胜率曲线。
- ARM64 和 32 位 Windows 安装包。

## 3. 用户体验与页面

### 3.1 视觉方向

采用“专业分析台”方案：深色工作区、暖木色棋盘、青绿色分析强调色。棋盘是主视觉，右侧分析栏常驻，窗口缩放时优先保证棋盘为正方形并保持坐标可读。

### 3.2 主窗口

主窗口由以下区域构成：

1. 标题栏：产品名、当前模式和窗口控制。
2. 工具栏：新对局、打开 SGF、保存、坐标显示、分析开关和设置。
3. 棋盘：落子、最后一手标记、合法落点反馈、候选点标记和坐标。
4. 玩家卡片：执棋颜色、当前回合、AI 思考状态和正式搜索剩余时间。
5. 分析面板：当前胜率、预计目差、三个候选点及其胜率和目差。
6. 对局面板：手数、规则、棋盘大小和贴目。
7. 操作栏：悔棋、停一手和认输。

关闭“分析”后隐藏胜率、目差和候选点，但保留 AI 是否正在思考及剩余时间。

### 3.3 新对局窗口

新对局窗口提供：

- 模式：人机对弈或本地双人。
- 执棋：执黑、执白或随机；仅在人机模式显示。
- 棋盘：19 路、13 路或 9 路。
- 固定规则：中国规则，贴目 7.5 目。

界面不显示 AI 难度选项。玩家执白时，KataGo 自动完成黑方第一手，再进入玩家回合。

### 3.4 对局结束

- 认输立即结束对局并写入结果。
- 连续两次停一手进入数子页面。
- 数子页面由 KataGo 所有权预测给出死子建议，用户可按整块切换死活状态；最终面积计分由本地规则引擎计算。
- 人机对局由玩家确认结果；本地双人由双方在同一设备上确认。存在争议时可恢复对局继续落子。
- 结束页面提供保存 SGF、再来一局和返回主界面。

## 4. 悔棋规则

“一次悔棋”指一次用户操作，而不是固定撤销一颗棋子。

### 4.1 人机模式

- AI 已对玩家上一手作出应手：撤销 AI 应手和玩家上一手，回到玩家上次落子前。
- AI 正在思考、尚未落子：先终止该分析，再撤销玩家刚下的一手。
- 因此，只要对局尚未结束，每次悔棋完成后都轮到玩家落子。
- 玩家执白且尚未走出第一手时，AI 的开局黑棋不可单独悔回空盘；此时禁用悔棋按钮。

### 4.2 本地双人模式

每次操作仅撤销最后一手，随后由被撤销着法的一方继续落子。

### 4.3 已结束对局

确认终局或认输后不直接悔棋。用户可选择“恢复对局”，该动作移除结果并回到结束前的局面。

## 5. 系统架构

### 5.1 表现层

- `Shell`：窗口、导航和全局命令。
- `BoardView`：自绘棋盘、命中测试、落子与分析标记。
- `GameViewModel`：将用户命令映射到应用服务，并发布可绑定状态。
- `AnalysisPanelViewModel`：展示胜率、目差、候选点和引擎状态。
- `NewGameViewModel`：验证新对局参数。

表现层只依赖应用层接口，不直接读写 SGF、启动进程或实现围棋规则。

### 5.2 应用层

- `GameSession`：对局状态机、回合推进、悔棋、停一手、认输和终局恢复。
- `AnalysisCoordinator`：调度分析、执行 30 秒截止、取消过期请求并发布结果。
- `GamePersistenceService`：自动保存、恢复和显式 SGF 保存。
- `EngineStartupService`：执行硬件探测、自检、后端选择和故障回退。

### 5.3 领域层

- `BoardState`：不可变棋盘快照、当前方、劫状态和局面历史哈希。
- `GoRules`：合法性、提子、自杀禁着、简单劫和位置超级劫。
- `MoveHistory`：着法、停一手、提子信息和可逆状态。
- `ChineseAreaScorer`：活子、地盘、死子标记和贴目计算。
- `GameResult`：数子、认输或无结果。

领域层不依赖 WPF、文件系统或 KataGo，确保规则可独立测试。

### 5.4 基础设施层

- `KataGoProcess`：常驻子进程、标准输入/输出、标准错误日志和生命周期。
- `KataGoAnalysisClient`：逐行 JSON 请求、异步响应关联、终止请求和容错解析。
- `BackendSelector`：选择 TensorRT（兼容时）、OpenCL 或 Eigen CPU。
- `SgfReader` / `SgfWriter`：SGF 编解码。
- `AtomicJsonStore`：设置、恢复快照和引擎探测缓存。

## 6. KataGo 集成与极限棋力

### 6.1 协议

软件使用 KataGo JSON Analysis Engine，而不是让 UI 解析控制台文本。每个请求包含唯一 ID、完整着法、当前方、棋盘尺寸、`chinese` 规则和 7.5 贴目。响应使用 `moveInfos`、`rootInfo.winrate` 和 `rootInfo.scoreLead` 生成候选点与形势信息。

### 6.2 30 秒正式搜索

1. AI 回合提交高上限 `maxVisits` 的分析请求，并要求每秒返回一次中间结果。
2. `AnalysisCoordinator` 从请求写入成功开始计时 30 秒。
3. 到时发送 KataGo `terminate` 动作并等待该请求最后一个 `isDuringSearch=false` 响应。
4. 选择最终响应中排序第一的合法候选点。
5. 若最终响应没有数据，使用最近一次有效中间结果；仍无结果则重启引擎并进入回退流程。

玩家回合的推荐分析可持续到玩家落子。落子、悔棋、载入棋谱或关闭对局会终止旧请求。每个请求关联 `GameRevision`；修订号不匹配的响应只记录诊断信息，不更新界面。

### 6.3 自动后端与模型选择

安装包内置：

- 适合兼容 GPU 的 KataGo 后端和已验证的最大 Transformer 强模型。
- 通用 OpenCL 后端。
- Eigen CPU 后端及已验证的轻量 Transformer 强模型。
- 配置模板、资源清单、SHA-256 和第三方许可。

选择顺序为：

1. 使用上次成功且资源清单未变化的组合进行快速自检。
2. 兼容 NVIDIA 设备优先尝试已打包的高性能 GPU 后端。
3. 其他兼容 GPU 尝试 OpenCL。
4. GPU 失败时尝试 Eigen CPU；支持 AVX2 时使用对应构建，否则使用通用构建。
5. 每个候选组合执行短基准测试；在内存稳定的前提下，以单位时间访问量最高者为最终组合。

首个发布清单固定使用 KataGo v1.17 系列：GPU 候选使用 `b11c768h12nbt3tflrs-fson-silu.bin.gz`，CPU 候选使用 `b10c384h6nbttflrs.bin.gz`。这里的“最强”定义为：在当前硬件、30 秒上限和稳定内存占用下，选择基准测试预计访问量与网络强度综合最优的组合，而不是盲目选择无法有效搜索的大模型。升级模型时必须更新资源清单、SHA-256 和真实后端基准测试。

### 6.4 资源调度

- AI 正式回合暂停玩家局面推荐，将全部 KataGo 搜索资源用于正式落子。
- 玩家回合最多运行一个分析请求。
- UI 更新频率限制为每秒一次。
- 用户可在设置页重新检测引擎，但不能选择弱化 AI 的难度。

## 7. 数据流

### 7.1 玩家落子

1. `BoardView` 将点击转换为棋盘坐标。
2. `GameSession` 请求 `GoRules` 校验。
3. 合法着法生成新的不可变 `BoardState` 和 `GameRevision`。
4. `GamePersistenceService` 原子写入恢复快照。
5. 表现层立即绘制新状态。
6. 若进入 AI 回合，`AnalysisCoordinator` 启动正式搜索；否则启动可选推荐分析。

非法着法不会改变状态，并在交叉点显示短暂反馈。

### 7.2 AI 落子

1. 分析客户端接收中间结果并节流更新右侧面板。
2. 30 秒到时终止搜索并取得最佳候选点。
3. 领域规则再次校验候选点。
4. 合法则提交着法并自动保存；非法则记录协议错误，重启引擎并重新分析一次。
5. 重试仍失败时保持棋局并提示切换到本地双人模式。

### 7.3 悔棋

1. 终止当前分析并等待其完成标记或进程重启。
2. 根据人机或双人策略计算目标历史节点。
3. 原子替换当前状态、增加 `GameRevision` 并自动保存。
4. 启动玩家当前局面的推荐分析。

## 8. SGF 与本地存储

### 8.1 SGF

写出 SGF FF[4]，至少包含 `GM`、`FF`、`CA`、`AP`、`SZ`、`KM`、`RU`、`PB`、`PW`、`DT` 以及完整主线着法；对局已有结果时再写入 `RE`。保存使用 UTF-8。

首版载入 SGF 的主变化。若文件含分支，载入时明确提示“首版仅打开主变化”；默认使用“另存为”，避免覆盖带变化树的原文件。非法坐标、尺寸不支持或语法错误会给出可理解的错误位置，不改变当前棋局。

### 8.2 本地目录

`%LocalAppData%\Yijing\` 下保存：

- `settings.json`：界面与分析显示设置。
- `engine-profile.json`：后端、模型、硬件摘要、版本和自检时间。
- `autosave\active-game.json`：未完成对局恢复快照。
- `logs\`：滚动日志；默认保留 7 天，单文件上限 5 MB。

显式 SGF 文件保存到用户选择的位置。所有 JSON 写入先生成同目录临时文件，再用原子替换完成。

## 9. 错误处理

- **GPU 初始化失败：** 自动尝试下一候选后端，只显示一次非阻塞提示。
- **KataGo 崩溃：** 保存局面、重启进程、重放完整着法并重试一次。
- **重复崩溃：** 禁用 AI 功能，保留 SGF 查看和本地双人模式，并提供诊断日志入口。
- **模型损坏：** 启动前 SHA-256 校验失败，提示修复安装；不启动对应后端。
- **分析超时：** 30 秒正常终止属于设计行为；终止响应再超时 3 秒则重启引擎。
- **自动保存失败：** 保持内存中的棋局，显示持久警告并允许用户立即另存 SGF。
- **异常 SGF：** 错误不替换当前会话。
- **应用退出：** 若仍有未结束对局，确保最新恢复快照已落盘后再关闭。

## 10. 测试策略

### 10.1 单元测试

- 9、13、19 路坐标和棋盘边界。
- 单子与多子提取、连环提子、自杀禁着。
- 简单劫、位置超级劫和历史哈希。
- 连续停一手、认输、终局恢复和中国面积计分。
- 人机与双人悔棋的所有边界。
- SGF 坐标、转义、元数据和往返一致性。
- 后端排序、基准结果比较和资源清单校验。

### 10.2 组件测试

使用可控的假 KataGo 进程验证：

- 异步乱序响应与 ID 关联。
- 中间分析、30 秒终止和最终结果选择。
- 请求取消、过期 `GameRevision` 丢弃。
- 无结果、非法 JSON、标准错误输出、崩溃和重启。

### 10.3 集成测试

- 使用真实 Eigen 后端完成 9 路短局。
- 在具备相应硬件的测试机验证 OpenCL 和高性能 GPU 后端。
- 验证引擎重启后重放着法得到相同当前方与合法着法集合。
- 验证安装后断网首次启动和 CPU 回退。

### 10.4 UI 与验收测试

- 100%、125%、150%、200% DPI 下棋盘命中和布局。
- 窗口最小尺寸、最大化和恢复。
- 键盘焦点、按钮可访问名称和高对比度可读性。
- 玩家执黑、执白分别完成一局。
- AI 已落子与 AI 思考中两类人机悔棋。
- 异常退出后恢复、保存 SGF、重新载入并核对局面。
- Windows 10/11 x64 自包含安装、卸载和升级。

## 11. 交付与版本边界

- 使用 .NET 10 LTS 的 WPF 自包含 x64 发布，目标机器无需预装 .NET。
- 生成单一 Windows 安装程序，内置已验证的引擎、模型和配置。
- 构建产物包含资源清单、SHA-256、KataGo/模型版本及第三方许可说明。
- 安装程序升级不得删除 `%LocalAppData%\Yijing\` 中的用户设置、恢复快照或日志。
- 首版完成标准：本规格中的单元、组件、集成和验收测试全部通过，且所有目标功能均可在断网环境使用。
